The Idea to Impact Challenge

Select a problem or opportunity. Pick a workflow. Sixteen hours later, the workflow is built, tested and deployed, with user guides.

Pick a workflow that your business runs, and we will take it to production. This page shows the sequence of steps. The clock runs for each step. Each step gives the next step a finished artefact. Because of this, the trace from the sponsor's problem to software in production is complete, and nobody has to assemble the trace afterwards. Four of the sixteen hours are your people's time.

A number with a ring is a step that needs people from the business. There are four such steps.

  1. 01

    Sponsor session

    1 hour Business time 1:00h

    Meet the sponsor. Agree the problem to solve, the opportunity, the success measures, and the stakeholders.

    Session transcript
  2. 02

    Problem & Opportunity Statement

    1 hour 2:00h

    Produce the statement and the stakeholder artefacts directly from the sponsor session transcript.

    Problem & Opportunity Statement Stakeholders & Personas
  3. 03

    Observation sessions

    1 hour each Business time 3:00h

    Stakeholders show you the workflows that they run today. You record the pain points and the possible improvements.

  4. 04

    Current state documented

    2 hours 5:00h

    Document how the work runs today and the systems that it runs on. Then update the Problem & Opportunity Statement with what you learned.

    Current State Workflows Current State System Architecture
  5. 05

    Domain Model and Workflows Value Stream

    4 hours 9:00h

    Design the domain model that the solution is built on. Design the value stream that its workflows form together.

    Domain Model Workflows Value Stream
  6. 06

    Workflow design and Model Specs

    1 hour 10:00h

    Design one workflow from the value stream. Create the model specs for the workflow, or update the specs that already exist.

    Workflow design Model Specs
  7. 07

    Build and unit test

    1 hour 11:00h

    Build the workflow and unit test it.

    Working workflow Unit tests
  8. 08

    System tests written and run

    1 hour 12:00h

    Write the system tests. Run the tests and record the results.

    System tests Test results
  9. 09

    User guide and video

    30 minutes 12:30h

    Write the user guide and produce the video of the guide. Then the people who use the workflow can start work on it.

    User Guide User Guide Video
  10. 10

    Users review and test

    1 hour Business time 13:30h

    Give the guide and the build to the users. The users review the guide and test the workflow against the way that they work.

    Review findings
  11. 11

    Triage, fix, re-test

    1 hour 14:30h

    Triage the findings and fix them. Update each artefact that the fix changes. Then run the system tests again.

    Updated artefacts System test results
  12. 12

    Users confirm the fixes

    1 hour Business time 15:30h

    The users who reported the findings confirm the fixes. The record is current when the users give their sign-off, not one week later.

    User sign-off
  13. 13

    Release notes, roadmap, production deploy

    30 minutes 16:00h

    Publish the release notes and the updated roadmap. Then deploy to production. Both documents come from artefacts that are already current. For this reason, we measure this step in minutes.

    Release notes Roadmap Production deploy
  14. Run complete 16:00h
  15. 14

    Monitor usage, security and performance

    continuous

    Monitoring starts from the moment that the workflow is live. We monitor usage, security and performance in production. The data that comes back is the input to the next run.

Total

16:00h

Two working days from the sponsor session to the workflow in production. Add one hour for each extra stakeholder that you observe.

Business stakeholder time

4:00h

Only four of the sixteen hours need time from your business: the sponsor session, the observation session, the review, and the confirmation. The other twelve hours run without your people.

The clock assumes one observation session. No step in the list is a status meeting, a handover, or a document that updates an old record. Step 14 is outside the clock, because the monitoring does not stop.
